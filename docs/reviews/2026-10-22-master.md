## Blockers (1)

### B1 `engine/text_injector.py` — missing imports disable slow-app/self-window detection on the primary platform

- Line 100 calls `psutil.Process(pid)`; **`psutil` is never imported in the file** (rg: imported only in `window_inspector.py`, `diagnose.py`, benchmarks, tests).
- Line 72 calls `os.getpid()`; **`os` is also never imported**.
- The broad `except Exception` wrapping the block swallows the resulting `NameError` at call time, so the affected detection path silently no-ops on every Windows dictation instead of failing loudly.
- Consequences: a shipped functional capability (slow-app / FlowPilot-self-window detection feeding the injection verification chain) is dead on the primary platform, and it erodes the very "truthful status" invariant that root AGENTS.md lists as the project's first rule — no error, no telemetry, no user-visible degradation, just over-optimistic verification.
- Fix is two import lines plus a regression test that asserts the detection path executes (not just that the app doesn't crash).

## Majors (3)

### M1 Unlocked, non-atomic `config.json` writes across 10 call sites → silent total settings loss on a torn write

- `engine/config.py:76` (`save_config`) does a plain in-place `open(cfg_file, "w")` overwrite: no lock, no temp-file + atomic rename.
- Production save sites (all pinned):
  - `engine/orchestrator.py:638` (`update_config` merge save), `:837` (per-dictation persist on the dictation worker path)
  - `engine/server.py:177` (server mutation endpoint)
  - `desktop_app.py:312, 320` (tray language / translate toggles)
  - `ui/floating_hud.py:365` (`_save_position`, fires on **every drag end**)
  - `ui/flowpilot_dashboard.py:298`, `ui/notetaker_view.py:1028`, `ui/setup_wizard.py:620`
- Failure mode: any interleaved write (worker thread vs GUI thread is the live pair) tears the JSON. On next launch `engine/config.py:68–70` catches the exception, prints to console, and returns `DEFAULT_CONFIG.copy()` — the user's full settings are silently gone and nothing restores them (a follow-up save then persists defaults over the wrecked file).
- Verified by mechanism + read; the race is not reproduced at runtime (stateful, cheap probe not possible), so the grading of "major, not blocker" reflects unproven actual frequency.
- Recommended fix is a single chokepoint: add a thread lock and write-to-temp-then-rename inside `save_config` — it heals the entire class at once.

### M2 `engine/server.py:49` — full orchestrator instantiated at module import

- `orchestrator = FlowOrchestrator(on_state_change=broadcast_state)` runs at import time: model preload thread and hotkey detection spin up just because something imported `engine.server`.
- This is documented as a gotcha in `engine/AGENTS.md`, but it remains live in the import path: it's why server-side suites must stage env vars in a precise order, and it makes `import engine.server` a side-effecting operation that any future tooling (docs builds, API introspection) will detonate.
- Verdict: kept as major despite documentation, because the hazard is load-bearing in production and the correct long-term shape is lazy/pluggable orchestrator acquisition.

### M3 `engine/writing_intelligence.py:512–513` — bare word "tab" rewrites prose into tabs with no false-positive guard

- `(?i)\b(?:press tab|tab key|tab)\b` → `\t` replaces the word "tab" **anywhere** it appears. Ordinary dictation like "the browser tab crashed" becomes "the browser\tcrashed" in polished/professional output — user-visible text corruption on the primary polish path.
- Contrast: the "period" pattern at `:531` carefully guards false positives (`(?<!\ba)` + negative lookahead). The asymmetry is the tell that "tab" was simply not adversarially reviewed.
- Note: `re.sub` alternation order means the multi-word forms replace correctly (leftmost-longest alternation consumes "press tab" first at that position); the defect is purely the unguarded single-word alternative.

## Minors (9)

### m1 `ui/notetaker_view.py:858, 881, 994` — decision slice bug corrupts copied/exported reports (probed)

- Parsing decisions back out of rendered Markdown: `line[13:]` on `- **Decision:** X`. The prefix `- **Decision:** ` is 16 characters; the probe printed `line[13:] = '** Ship the pilot on Friday'`.
- `engine/meeting_notetaker.py:624` re-renders verbatim, so "Copy Full Report" (at 858), "Export Report" (at 881), and the email fallback (at 994) emit `- **Decision:** ** X` with leaking `**` markers. Stored meeting data is unaffected; corruption is confined to copies/exports/email drafts.
- Fix: `line[16:]` at all three sites (or parse with a regex).

### m2 Last-writer-wins settings write can shrink config to a partial dict

- `ui/flowpilot_dashboard.py:297–298` saves the raw incoming dict to disk **after** `orchestrator.update_config`'s merged save (`engine/orchestrator.py:638`), and `desktop_app.py:296` stores the raw dict in app state instead of the merged result.
- Currently benign: both current callers (`settings_dialog.py:499/555 → on_save(self.config)`, `setup_wizard.py:622 → emit(self.config)`) hold full dicts derived from `load_config()`.
- Latent risk: the first caller that passes a partial dict writes a partial config with no error; also the double-save doubles the M1 race window.

### m3 `engine/server.py:75, 115` — `hmac.compare_digest` raises `TypeError` on non-ASCII token → 500 instead of 401

- A client that sends a non-ASCII bearer token gets an unhandled server error from what should be an auth rejection. Cosmetic-on-Pro, but it is the difference between "rejected" and "server broke" in any audit log.

### m4 `engine/server.py:223` — unbounded `await file.read()` in `/v1/audio/transcriptions`

- A single request can pin unbounded memory before any size check. Loopback-only exposure (`listen="127.0.0.1"`) keeps this minor; a 10-line size cap would close it.

### m5 `engine/hotkey_service.py:249, 320` — stale `GetLastError()` pattern

- Calling `kernel32.GetLastError()` through `windll` after a failing call is unreliable (previous call may have overwritten it). Correct pattern: load kernel32 with `ctypes.WinDLL(..., use_last_error=True)` and read `ctypes.get_last_error()`. Impact is confined to error-message accuracy in the hotkey path; registration/cleanup logic is unaffected.

### m6 `engine/personalization.py:29` — `PERSONALIZATION_FILE` caches the config-path resolution at import

- `get_config_file().parent` is bound at module import, identical hazard class to the documented `engine/config.py:15` cache, but this one is missing from the engine gotchas. Env-staged tests must therefore stage before importing either module; today they do, which is why nothing is red — but a single-suite run touching only personalization would break the invariant silently.

### m7 `ui/floating_hud.py:113–115` — 30 FPS animation timer runs unconditionally, even idle and hidden

- The 33 ms `QTimer` ticks and calls `update()` regardless of visibility or state, a constant wake cost on a desktop-resident app. Also the `pet_sprites` import fallback (lines 41–47 → `ps = None`, early return at `:565`) renders an invisible-but-clickable HUD with no degraded indicator.

### m8 Unused dependency: `requests`

- Declared at `requirements.txt:31` and `pyproject.toml:51` (`requests>=2.31.0`); rg finds **zero** import sites across all `.py` files. Dead dependency in the loopback-only app — remove or document the reason. (Deps: new in v3.x wrapper, appears inherited from an abandoned server-side fetch path.)

### m9 Documentation truth: line-count table and suite stats are stale in both directions

- `ui/AGENTS.md` ">800 lines" table is wrong on **every count** (measured): pet_sprites 1480 (says 1400), companion_renderer 1460 (says 1359), pixel_creator 1042 (says 901), notetaker_view 1033 (says 923), floating_hud **759** (says 849 — under the cap it's warned about), while `engine/orchestrator.py:850` is actually over the cap and absent from the list.

- Per repo rules these are draft docs that later skill runs treat as curated; stale numbers here propagate into architecture decisions.
- Engine gotcha for `personalization.py:29` is missing too (same hazard class as `engine/config.py:15`).
- Prior counts settled by a definitive byte count this session: `except Exception` appears **258 times across 111 .py files** (working tree excluding vendored, backup, build and model dirs, root files included); the reviewer's earlier 272/55 figure would not reproduce under any consistent scope and is replaced by the 258/111 measurement.

## Strengths (verified, not flattery)

- **Egress discipline is enforced in depth, not once.** `engine/stt_engine.py` rejects cloud mode outright with `local_files_only=True`; `local_llm.py` pins `ProxyHandler({})`, blocks redirects, validates loopback with literal-IP checks; `server.py` binds `127.0.0.1` with token + origin checks; `/health` opener is deliberate. This is the strongest layer of the app.
- **Truthful-status chain is honored end-to-end.** `InjectionStatus.SENT_UNVERIFIED` survives the whole traverse: `desktop_app.py:209–213` downgrades unconfirmed pastes and wording is consistent across HUD (`floating_hud.py:181–199`), tray (`tray_manager.py:199–202`), and reinject messaging (`desktop_app.py:325–341`).
- **Test strategy is real.** 51 suites / 401 s on fresh env-staged config (`FLOWPILOT_CONFIG_FILE` etc. — the config.py:15 cache is tame in that regime), self-test synthesizes real SAPI audio through the real STT pipeline (`desktop_app.py:406–468`).
- **StateBridge pattern respected everywhere.** Engine → GUI crossing is signal-based with no engine thread ever touching widgets (`desktop_app.py:199–233`, `notetaker_view.py:30–51`).
- **Hotkey handling is defensive.** `parse_hotkey_string` raises on invalid input, `RESERVED_FLOWPILOT_SHORTCUTS` guards conflicts, and duck defaults are consistent (`engine/orchestrator.py:40` matches `tray_manager.py:105`).
- **FactGuard fails safe.** On number/entity mismatch it warns and falls back to raw text (wrote-and-warned exists) — the conservative direction. `_finalize_punctuation` is symbol-aware across CJK/Indic/Arabic (`writing_intelligence.py:875–880`).
- **Window management is done right.** `WS_EX_NOACTIVATE` + focus-absorbing double-click + snap corners, and HUD resizes by style via `CompanionRenderer.get_preferred_size`.
