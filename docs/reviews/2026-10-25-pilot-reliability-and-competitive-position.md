# FlowPilot pilot reliability and competitive position

Date: 2026-10-25. Source branch: `feature/pilot-reliability-hardening`. This review separates the published RC4 bytes from development source on this branch.

## Release identity and what the evidence supports

The public [v3.1.0-RC4 GitHub Release](https://github.com/abishekvr0910/flowpilot/releases/tag/v3.1.0-RC4) is a prerelease with one ZIP, 770,634,494 bytes, SHA-256 `55918eb873499001a34e85f6f636db701d4f5937b340c3a051bac332db8f8c88`. The [RC4 manifest](../release/RELEASE_ARTIFACT_MANIFEST.md) records an unsigned executable, a 56/56 strict interactive rerun after one initial Notepad focus failure, a green hosted build with hardware skips, and an offline self-test. The first failure remains part of the evidence; one clean rerun is not a paste reliability percentage. RC4 does not contain the work on this branch.

The product has a defensible local processing advantage: the desktop dictation path uses local Faster-Whisper and bundled models, and selected paths are covered by socket egress tests. This does not prove whole-process zero outbound bytes. The cited 4× memory advantage is **not established** by a matched packaged-app comparison: the local benchmark measured an unloaded Python process or several host Python processes while sampling a Wispr process tree. Stop-to-visible-text parity is also unmeasured on paired fixtures. Do not publish a numerical memory, speed, or accuracy win until the [runtime protocol](../testing/RUNTIME_PERFORMANCE_PROTOCOL.md) and [competitive scope](../scope/competitive.md) produce comparable samples.

## Adversarial findings and development repairs

| Area | Verified source behavior before this branch | Development repair | Open physical proof |
| --- | --- | --- | --- |
| USB microphone loss | The callback printed a status warning; a stalled stream had no health check or deadline. | Callback errors and missing frames abort the session without inserting partial text. Open and close calls have deadlines; a hung driver locks out new recording until restart. Qt startup warms the microphone in a background thread. | Unplug and reconnect a real USB microphone during idle, startup, and a long recording; inspect audio and recovery behavior. |
| Administrator target | The injector checked window focus but had no integrity-level preflight. Windows UIPI can block input into a higher-integrity process. | Read the target process integrity before clipboard staging or keys. Higher or unreadable integrity returns `FAILED_RECOVERY_AVAILABLE` with an in-memory recovery copy. | Check normal and elevated targets on the physical desktop; confirm no silent delivery claim or clipboard change. |
| Ambiguous paste outcome | An exception after starting the paste chord could trigger a second Unicode attempt and duplicate text. | Once key or direct-edit dispatch may have started, return `SENT_UNVERIFIED` and require the user to check the target before retrying. An injection failure no longer writes text to the clipboard without the user asking. | Long-run Notepad, VS Code, browser, Terminal and Word attempts with duplicate and recovery counts. |
| Opt-in pilot metrics | `dictation_telemetry.log` appended without a size limit. | Local rotating log: 1 MB active file plus three backups, allowlisted fields only, process basename only, no transcript or session identifier. `save_history_text: false` still bypasses metrics persistence. | Long-session disk growth and upgrade handling for an already oversized legacy file. |
| Indic model setup | The first-run wizard checked `base` even when the user later selected Hindi, Tamil, or Malayalam. An empty model directory could appear verified. | Settings recommends `small`; setup selects it only when the local `model.bin` exists and refuses to complete when the recommended weights are missing. | Native-speaker English, Hindi, Tamil, Malayalam accuracy, code switching, and latency on declared hardware. |
| Publisher identity | RC4 Authenticode status is `NotSigned`; no code-signing certificate was found in the current-user personal certificate store on this machine. | No source-code fix can establish publisher identity. | Obtain publisher signing, sign **final bytes**, verify signature and reputation behavior on clean machines, then rebuild hashes and release evidence. |

Microsoft documents that [SmartScreen reputation](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation) can warn about unsigned or unfamiliar downloads; a signature establishes identity but does not guarantee the prompt disappears immediately. Microsoft's [SendInput documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) states input is limited by UIPI to equal or lower integrity targets and that UIPI blocking is not identified by the API error. The elevated-target behavior above is therefore an intentional recovery path rather than a claim of automatic paste into Administrator windows.

## Competitive assessment

| User need | FlowPilot evidence | Wispr Flow evidence | Decision |
| --- | --- | --- | --- |
| Private offline Windows dictation | Bundled local ASR and offline self-test; selected-path egress test | Wispr's [privacy policy](https://wisprflow.ai/privacy) describes server processing of dictation audio | FlowPilot has a meaningful local-first distinction. Publish the exact testing boundary. |
| Broad language quality | Registry and `small` model support; DE/ES/FR subset measured, Indic speech not yet measured | Wispr documents [more than 100 dictation languages](https://docs.wisprflow.ai/articles/2772472373-what-is-flow) | Do not claim multilingual superiority; prioritize real Hindi/Tamil/Malayalam recordings. |
| Polished writing and context | Local FactGuard, vocabulary, bounded commands, optional local context | Wispr documents [context awareness](https://docs.wisprflow.ai/articles/4678293671-Context-Awareness) and [Auto Cleanup](https://docs.wisprflow.ai/articles/4283510616-Auto-Cleanup%3A-control-how-much-Flow-edits-your-dictation) | Run paired corrections and factual-retention tasks. No current winner established. |
| Microphone and delivery recovery | New failure paths have unit tests; physical pilot trials pending | Wispr documents [disconnect handling and retry](https://docs.wisprflow.ai/articles/4351452717-troubleshooting-mic-issues) | FlowPilot cannot claim parity until USB and cross-app trials pass. |
| Platform reach | Windows is the release target | Wispr documents Windows, macOS, iOS, and Android | FlowPilot is not broadly better across platforms. Keep the initial target private developer dictation on Windows. |

## Verification ledger

Development tests cover bounded open/close, callback loss, stalled capture, elevated and unknown target refusal, duplicate prevention, telemetry rotation and redaction, and Indic weight availability. The focused audit passed 53 cases with two physical window tests deselected. The first headless full runner reported 57 suites: 50 passed, 5 skipped, 2 failed because `dist/FlowPilot/` still held an older unpacked executable with unused Qt Virtual Keyboard files; the packaged smoke and integrity suites correctly rejected it. After the final clean PyInstaller rebuild, the full runner passed **52 suites, skipped 5 physical desktop suites, failed 0**, in 98.88 seconds. `npm test` passed local REST and WebSocket integration.

The rebuilt development executable at `dist/FlowPilot/FlowPilot.exe` is 24,905,329 bytes with SHA-256 `CE8431C632981D0B1893847E9D5688282A4471B0448D437036B20974CBA8C4F4`; its Authenticode status is `NotSigned`. The packaged smoke test passed the bundled model, VAD, mutex, and process lifecycle checks. An offline self-test loaded the bundled base model and transcribed the SAPI fixture with an isolated empty Hugging Face cache, exit code 0 and zero cache files. This unpacked development build is not a new release archive or a replacement for RC4. The published RC4 ZIP still hashes to `55918EB873499001A34E85F6F636DB701D4F5937B340C3A051BAC332DB8F8C88`.

No physical USB, live elevated-window, native-speaker, or paired Wispr trial has been completed on this branch. The five local headless skips cannot be counted as passes. [Hosted CI run 40146674989](https://github.com/abishekvr0910/flowpilot/actions/runs/40146674989) built the Windows binary, passed the Node integration and standalone smoke checks, and reported 48 passed, 9 skipped, 0 failed across 57 suites. Its hardware and desktop skips also require physical validation.

## Next decision

Keep RC4 as a pilot prerelease. Promote a new candidate only from a frozen source commit after fresh package smoke, offline self-test, `--require-all` on an interactive desktop, hosted CI, and the physical failure trials above. Publisher signing and representative pilot evidence remain GA gates. A claim that FlowPilot is universally better than Wispr Flow or every competing application is unsupported; the measurable objective is safer private Windows developer dictation with no worse correction effort, factual errors, or delivery failures.
